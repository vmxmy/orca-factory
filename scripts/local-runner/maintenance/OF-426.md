## 结论

四个槽位停摆的根因是主机 GitHub 凭证不可读，不是 `scripts/local-runner/` 的代码缺陷。gh 的 token 存在 gnome-keyring 的 login keyring 中。机器重启后没有桌面登录，keyring 保持锁定，supervisor 调用的 `gh api` 因此不带认证。凭证恢复后，四个槽位按既有恢复流程自愈，不需要显式维护。

## 复发条件

本机开启 Linger，常在无桌面登录的状态下重启。只要 gh token 存在依赖登录解锁的 keyring 中，每次重启都会重复本次停摆，driver 的 GitHub API 同样断供。`driver doctor` 的 `credentials` 项会把此状态报为「GitHub 凭证不可读（keyring 可能未解锁）」。

恢复方法：在本机登录一次桌面会话以解锁 login keyring，或在用户会话中重新执行 `gh auth login -h github.com`。凭证恢复后，槽位在 30 秒重启周期内自愈，不需要停止槽位或归档租约。是否改用不依赖登录的凭证存储，由用户决定。
