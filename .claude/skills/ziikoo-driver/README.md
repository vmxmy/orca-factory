# ziikoo-driver

Claude Code mod。斜杠命令 `/ziikoo-driver` 打开「Driver」面板，五页分两组。会话里第一次打开时在流水线页，之后再打开回到上次所在的页。

运行组看 driver 现在在做什么：

- 流水线：顶部是在途、部署屏障、待领计数，下一行是趋势小图：近 30 分钟每分钟一格，格高是该分钟内读到的最大在途数，没读到的分钟画灰点 `·`，面板窄时只画最近能放下的几格。每个项目一个圆角框，上框线左边是项目名和前缀，右边是检出与 core 同步徽标（doctor 读取中时灰显「检查中…」）；面板窄到两者在框线上放不下时，徽标退回框内第一行靠右。每张票一行：票号、阶段轨道（领、施工、门禁、审查、合并、部署）、阶段名、在当前阶段停留的时长（10 小时以上只写小时，满 24 小时改写天，如「1 天 2 小时」，10 天以上只写天）；下一行灰显标题，卡住时再多一行原因。轨道每段 2 到 6 列，随面板宽度伸缩；每段 5 列以上时轨道上方写全称，更窄时写单字（领 施 门 审 合 部）；连 2 列都放不下时只显示阶段名。没配部署的仓库不画部署点。颜色只表示状态：完成绿、当前蓝、需要注意黄（correction、处置 Agent、快照过期）、失败红。
  - 详情：每行的票号是一个按钮，用 ↑↓ 把焦点移到票号上按回车（或点击），页面换成这张票的详情。打开面板或切到流水线页时，焦点直接落在第一张票上（按仓库顺序，仓库内按 status 的顺序）；从详情返回时落回刚才那张票；10 秒轮询不移动焦点。上面是「← 返回」（热键 `q`），下面一个框写阶段与停留时长、归属、仓库和原因；票已不在 status 列表里时写「已不在在途列表」。再下面的「时间线」框每条一行：本地时间与中文事件名（认领、worker 失败、gate 通过、进入排队合并等），worker 失败、gate 未通过这类需要回头看的事件黄字，合并冲突、执行器崩溃这类错误红字；只显示最后 15 条，更早的在最上面写「更早 N 条」。切到别的页时详情关闭。
  - 筛选：内容最上面是「筛选」按钮（热键 `f`）和它右边一直显示的输入框，按 `f` 把焦点移进输入框。按票号或标题过滤（不区分大小写），边输入边生效；输入框旁的提示是「确定」，回车后焦点落到第一张匹配的票上，再按回车即进入详情；没有匹配的票时焦点落到「筛选」按钮上。提交后输入框会被清空，按钮上显示当前生效的筛选（如「筛选：ZY」），在空输入框里回车即清除筛选。没有匹配票的项目框里写「无匹配」。切页时筛选清空。
- 健康：分「运行状态」（构建短 sha、服务状态、维护模式、状态快照）、「doctor 检查」（每项一行：中文名、通过 / 注意 / 失败 / 未知、原因）、「问题」三个框。

配置组看本机 driver 的生效配置：

- 模型：按仓库切换，「角色」框列出各角色的 Agent、模型、强度和来源键，底部是打回升档与小票审查阈值摘要。driver 施工首轮总用 default 档，strong 只在打回后升档时使用。
- 调度：`driver.toml` 的 8 个调度键，分为并发与限速、GitHub、Orca 与执行器、账本四个框。每行依次是中文名、带单位的值、来源和灰色的原键名（面板窄到原键名不足 14 列时不画这一列）；来源是 driver.toml 时高亮，是默认值时灰显。
- 环境：工厂目录、`driver.env`、服务环境与代理、工具路径各一个框；`driver.env` 的键只显示「已设置 / 未设置」，不显示值。最上面是「筛选」按钮（热键 `f`，把焦点移进右边一直显示的输入框）和输入框，按变量名过滤，回车后焦点移到「筛选」按钮上，可以直接按 `1`–`5` 切页；提交后输入框会被清空，按钮上显示当前生效的筛选，空回车清除；没有匹配的分组照样画框并写「无匹配」。

需要处理的状态画成标签：黄底或红底的反色文字，例如健康页的「注意」「失败」「未知」和项目徽标的「在 <分支>」「落后 N」「未提交改动」「core 待同步 #N」「core 未知」「检出未知」。正常状态（`main ✓`、`core ✓`、「通过」）是灰字。

头部两行。第一行是页签，每组前面是组名，当前组的组名加粗。第二行左边是服务状态点（`active` 时绿，否则红）、服务状态文字（如 `active`）和构建短 sha；右边在运行组显示快照新鲜度（「快照 8 秒前」；过期时黄字加「· 已过期」；没有快照时「没有可用的快照」），停在运行组时每 10 秒自动刷新；在配置组显示 config 的取数时间，最右是刷新按钮。两组页面在读取进行中都会在刷新按钮左边显示一个转圈的加载动画。

## 状态栏与提醒

面板关着时也能看到 driver 的动向。每次读到 status（后台、面板轮询、打开面板、按 `r`）都更新输入框下方的状态栏：

- `Driver 在途 N`：N 是没有阶段标记的票数，与流水线页的「在途」相同。有部署屏障时加 ` · 部署屏障 B`，快照过期时加 ` · 快照过期`。
- `Driver 空闲`：没有在途票（过期时同样加后缀）。
- `Driver 没有可用的快照`：driver 还没写出快照。
- `Driver 状态读取失败`：命令失败或输出无法解析。

每次读到的票与上一次成功读到的比较，有变化时弹一条提醒（toast），写成「<票号> <变化>」，同一次有多条时用「；」连成一条。会话里第一次读取只记下列表，不弹提醒；读取失败或 driver 没有快照（状态栏写「Driver 没有可用的快照」）时不比较，也不更新比较基准，快照恢复后仍和最后一次真实快照比较。变化有：

- 进入：已合并、交给处置 Agent、转人、部署暂停、打回修改（进入写 correction）。票在上一次已处于同一状态时不再提醒。
- 离开：上一次已合并或有未通过部署的票不在新列表里，记「已完成」。其他票离开列表不提醒。

## 打开

- 本仓库：交互会话自动加载 `.claude/skills/ziikoo-driver/`，直接输入 `/ziikoo-driver`。
- 其他仓库：`claude --plugin-dir <本目录的绝对路径>`，再输入 `/ziikoo-driver`。

面板打开后持有键盘：`r` 刷新，`1`–`5` 切页（运行组 1 流水线、2 健康；配置组 3 模型、4 调度、5 环境），Tab 或 ↑↓ 在按钮、票号和仓库下拉之间移动，回车按下焦点所在的按钮，`f` 把焦点移进筛选框（流水线与环境页），`q` 从详情返回，Esc 回到输入框。焦点在筛选框里时输入的数字和字母进入框内，不触发热键。底部的帮助条随当前视图换成对应的按键说明。

## 数据来源

面板只运行 `orca-factory-driver` 的四个只读命令，不读任何配置文件：`config --json`（每页都用，打开面板和按 `r` 时读取；配置组的页只读它）、`status --json`（流水线页的在途票、右上角的快照新鲜度、状态栏和提醒；打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时读取，停在运行组时每 10 秒重读一次，关掉面板后这个轮询停止；此外会话开始时读一次，之后在后台每 30 秒读一次，面板开着且停在运行组时后台这次跳过；热重载后面板仍开着时，后台把 10 秒轮询重新挂上，停在运行组时会话开始时那次读取也交给 10 秒轮询）、`doctor --json`（流水线页的项目徽标和健康页的检查列表；只在打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时运行，不随 10 秒定时重读，退出码 1 也照常解析）。详情的时间线来自执行器日志：`bash -c 'set -o pipefail; orca-factory-driver logs "$1" --json | { grep -E … || [ $? -eq 1 ]; }' _ <票号>`，只在打开详情和在详情里按 `r` 时运行。票号只作为位置参数传入，不拼进脚本；不符合 `ABC-123` 形状的票号不运行命令，时间线写「票号格式不对」。用 grep 只留下 `transition`、`ticket completed`、`command started`、`command exited` 四类行，是因为长票的日志大部分是轮询记录，而面板读取命令输出最多只保留前 4 MiB，不过滤会截掉最新的部分；grep 没有匹配是正常结果，显示「没有执行器日志」；driver 失败时显示失败视图。日志里每个事件出现两次，面板按时间、类型和事件名去重。日志里没有 PR 编号，所以详情不显示 PR 链接。config 输出必须符合 `driver-config-v1` 契约（见 `driver/CONTRACTS.md`）。命令失败时面板画一个红框，写出退出码、stderr 前几行和「r 重试」；schema 或字段形状不对，或者出现面板不认识的调度键时，红框里写「输出无法解析」和原因。右上「↻ 刷新」重新取数。
