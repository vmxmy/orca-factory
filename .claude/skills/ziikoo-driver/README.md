# ziikoo-driver

Claude Code mod。斜杠命令 `/ziikoo-driver` 打开「Driver」面板，五页分两组。会话里第一次打开时在流水线页，之后再打开回到上次所在的页。

运行组看 driver 现在在做什么：

- 流水线：顶部是在途、部署屏障、待领计数，下一行是趋势小图：近 30 分钟每分钟一格，格高是该分钟内读到的最大在途数，没读到的分钟（包括 driver 没有快照的时候）画灰点 `·`，面板窄时只画最近能放下的几格。每个项目一个圆角框，上框线左边是项目名和前缀，右边是检出与 core 同步徽标（doctor 读取中时灰显「检查中…」）；面板窄到两者在框线上放不下时，徽标退回框内第一行靠右。每张票一行：票号、阶段轨道（领、施工、门禁、审查、合并、部署）、阶段名、在当前阶段停留的时长（10 小时以上只写小时，满 24 小时改写天，如「1 天 2 小时」，10 天以上只写天）；下一行灰显标题，卡住时再多一行原因。轨道每段 2 到 6 列，随面板宽度伸缩；每段 5 列以上时轨道上方写全称，更窄时写单字（领 施 门 审 合 部）；连 2 列都放不下时只显示阶段名。没配部署的仓库不画部署点。没有票的项目框里写「空闲」；status 带下次巡检时间（`nextScanAt`）时写成「空闲 · 下次巡检约 2 分钟后」（以这次读取的时刻算），时间已过写「空闲 · 即将巡检」。颜色只表示状态：完成绿、当前蓝、需要注意黄（correction、二线处理中、快照过期）、失败红。
  - 详情：每张票的这一行（票号到停留时长）整行是一个按钮，焦点所在的行整行反色；用 ↑↓ 把焦点移到某一行按回车（或点击行内任意位置），页面换成这张票的详情。标题行和原因行不在按钮里。打开面板或切到流水线页时，焦点直接落在第一张票上（按仓库顺序，仓库内按 status 的顺序）；从详情返回时落回刚才那张票；10 秒轮询不移动焦点。上面是「← 返回」（热键 `q`），下面一个框写阶段与停留时长、归属、仓库和原因；票已不在 status 列表里时写「已不在在途列表」。再下面的「时间线」框每条一行：本地时间与中文事件名（认领、worker 失败、gate 通过、进入排队合并等），worker 失败、gate 未通过这类需要回头看的事件黄字，合并冲突、执行器崩溃这类错误红字；只显示最后 15 条，更早的在最上面写「更早 N 条」。时间线下面的「最近异常」框列出同一份日志里最近 5 条需要回头看的记录，每条一行：本地时间、中文说明和灰字补充。记录分三类：退出码非 0 的外部命令（「git 退出码 128」，补充 stderr 第一行）和超时的外部命令（「orca 超时」），结果不是 ok 的步骤（「reviewer 出错」，补充「结论 red」），打回修改（「打回：gate red」，补充 fail_summary 第一行）。同一次失败先记失败的命令、一秒内再记出错的步骤，两条合成一行，写步骤名，补充里先写步骤的结论（若有），再写命令的退出码或超时和 stderr 第一行（如「open-pr 出错 gh 退出码 1：pull request create failed…」）。命令和步骤出错红字，打回黄字，补充放不下时截断。没有这几类记录时不画这个框。切到别的页时详情关闭。
  - 筛选：内容最上面是「筛选」按钮（热键 `f`）和它右边一直显示的输入框，按 `f` 把焦点移进输入框。按票号或标题过滤（不区分大小写），边输入边生效；输入框旁的提示是「确定」，回车后焦点落到第一张匹配的票上，再按回车即进入详情；没有匹配的票时焦点落到「筛选」按钮上。提交后输入框会被清空，按钮上显示当前生效的筛选（如「筛选：ZY」），在空输入框里回车即清除筛选。没有匹配票的项目框里写「无匹配」。切页时筛选清空。
- 健康：分「运行状态」（构建短 sha、服务状态、维护模式、状态快照）、「doctor 检查」（每项一行：中文名、通过 / 注意 / 失败 / 未知、原因）、「问题」三个框。

配置组看本机 driver 的生效配置：

- 模型：按仓库切换，「角色」框列出各角色的 Agent、模型、强度和来源键，底部是打回升档与小票审查阈值摘要。driver 施工首轮总用 default 档，strong 只在打回后升档时使用。
- 调度：`driver.toml` 的 8 个调度键，分为并发与限速、GitHub、Orca 与执行器、账本四个框。每行依次是中文名、带单位的值、来源和灰色的原键名（面板窄到原键名不足 14 列时不画这一列）；来源是 driver.toml 时高亮，是默认值时灰显。
- 环境：工厂目录、`driver.env`、服务环境与代理、工具路径各一个框；`driver.env` 的键只显示「已设置 / 未设置」，不显示值。最上面是「筛选」按钮（热键 `f`，把焦点移进右边一直显示的输入框）和输入框，按变量名过滤，回车后焦点移到「筛选」按钮上，可以直接按 `1`–`5` 切页；提交后输入框会被清空，按钮上显示当前生效的筛选，空回车清除；没有匹配的分组照样画框并写「无匹配」。

需要处理的状态画成标签：黄底或红底的反色文字，例如健康页的「注意」「失败」「未知」和项目徽标的「在 <分支>」「落后 N」「未提交改动」「core 待同步 #N」「core 未知」「检出未知」。正常状态（`main ✓`、`core ✓`、「通过」）是灰字。

头部两行。第一行是页签，每组前面是组名，当前组的组名加粗。第二行左边是服务状态点（`active` 时绿，否则红）、服务状态文字（如 `active`）和构建短 sha；右边在运行组显示快照新鲜度（「快照 8 秒前」；过期时黄字加「· 已过期」；没有快照时「没有可用的快照」），停在运行组时每 10 秒自动刷新；在配置组显示 config 的取数时间，最右是刷新和复制按钮。两组页面在读取进行中都会在刷新按钮左边显示一个转圈的加载动画。

## 状态栏与提醒

面板关着时也能看到 driver 的动向。每次读到 status（后台、面板轮询、打开面板、按 `r`）都更新输入框下方的状态栏：

- `Driver 在途 N`：N 是没有阶段标记的票数，与流水线页的「在途」相同。有部署屏障时加 ` · 部署屏障 B`，快照过期时加 ` · 快照过期`。
- `Driver 空闲`：没有在途票（过期时同样加后缀）。
- `Driver 没有可用的快照`：driver 还没写出快照。
- `Driver 状态读取失败`：命令失败或输出无法解析。

每次读到的票与上一次成功读到的比较，有变化时弹一条提醒（toast），写成「<票号> <变化>」，同一次有多条时用「；」连成一条。会话里第一次读取只记下列表，不弹提醒；读取失败或 driver 没有快照（状态栏写「Driver 没有可用的快照」）时不比较，也不更新比较基准，快照恢复后仍和最后一次真实快照比较。变化有：

- 进入：已合并、升级到二线 Agent、转人、部署暂停、打回修改（进入写 correction）。票在上一次已处于同一状态时不再提醒。
- 离开：上一次已合并或有未通过部署的票不在新列表里，记「已完成」。其他票离开列表不提醒。

## 打开

- 本仓库：交互会话自动加载 `.claude/skills/ziikoo-driver/`，直接输入 `/ziikoo-driver`。
- 其他仓库：`claude --plugin-dir <本目录的绝对路径>`，再输入 `/ziikoo-driver`。

面板打开后持有键盘：`r` 刷新，`c` 复制当前视图，`1`–`5` 切页（运行组 1 流水线、2 健康；配置组 3 模型、4 调度、5 环境），Tab 或 ↑↓ 在按钮、票行和仓库下拉之间移动，回车按下焦点所在的按钮，`f` 把焦点移进筛选框（流水线与环境页），`q` 从详情返回，Esc 回到输入框。焦点在筛选框里时输入的数字和字母进入框内，不触发热键。底部的帮助条随当前视图换成对应的按键说明。

按 `d` 或头部「工坊沙盘」按钮打开浏览器里的工坊沙盘。

## 工坊沙盘

工坊沙盘是固定等距的 three.js 沙盘。Scene 的每个项目画成一座岛，岛之间是海。服务运行在本机 Bun 中，只运行 `orca-factory-driver status --json`（每 5 秒）和 `config --json`（每 60 秒），不读配置文件。页面打开时读 `/snapshot` 并订阅 `/events`，先到的 Scene 画出首屏，之后的 Scene 原地更新。页面只读，不提供推进票据的操作。

### 服务与访问

默认不需要任何配置，按 `d` 即可取得工坊沙盘 URL。服务绑定全部接口 `0.0.0.0`，广播地址依次选择 `nebula1` 的 IPv4、第一个非回环 IPv4、`127.0.0.1`。端口优先使用 `43210`，被占用时自动改用随机端口。

面板先复制完整 URL 并显示提醒。`SSH_CONNECTION` 或 `SSH_TTY` 任一非空即视为 SSH 会话，此时只复制 URL，提醒末尾写「SSH 会话，请在远程浏览器粘贴」，请在能访问该地址的远程浏览器打开。非 SSH 会话复制后会通过 `xdg-open` 用同一个广播 URL 打开本机浏览器。显式绑定回环地址也按此 SSH 规则处理。Nebula relay 对应用透明，仍然使用对端 Nebula 地址。

`/config` 中的两个选项只作覆盖，不填即可用，下一次启动工坊服务时生效：

- `bind`（工坊沙盘服务绑定地址）：默认 `auto`，使用上述自动规则；也可填 IP、接口名或 `0.0.0.0`。接口名取该接口第一个 IPv4 地址；显式 `0.0.0.0` 同样按上述优先级选择广播地址。
- `port`（工坊沙盘服务端口）：默认 `0`，优先 `43210`，占用时退到随机端口；可设为 1–65535 的固定端口，固定端口被占用时会报错。

服务运行期间再按 `d` 会复制已有 URL，并按当前会话的 SSH 状态决定是否打开本机浏览器；修改绑定配置后需等旧服务退出，再按 `d` 启动。

每次启动生成随机 token，它是服务唯一的访问门禁。页面、脚本、样式、vendor 文件、快照和 SSE 都要求 URL 的 `t` 参数或 `X-Token` 头；缺失或不符返回 404，非 GET 请求也返回 404。URL 含 token，不要外传；自动模式绑定全部接口，局域网主机凭 token 也能访问。Nebula 入站防火墙由主机 `/etc/nebula/config.yml` 决定，本 mod 不修改它。连续 15 分钟没有 SSE 订阅者时服务自动退出。

浏览器需要 WebGL2、ES 模块与 import map、EventSource 与 ResizeObserver 支持。页面不写入浏览器持久化存储。

已知限制：子进程随会话或热重载结束，再按 `d` 重起；复制失败时提醒给出原因与 URL，没有 `xdg-open` 或打开失败时也可手动粘贴 URL。固定端口只固定地址与端口，每次重启 token 都会变化，旧的收藏 URL 需更新。Scene 未提供负责人、历史时间线、PR 链接或完整部署对象时，页面不会补造这些字段。票据很多时可滚动侧栏或用搜索定位。

### 页面模块

- `scene/page/index.html`：样式表、入口模块与 import map。服务返回页面时把 `__TOKEN__` 换成本次 token。
- `scene/page/live.mjs`：读快照、接事件流、挂载沙盘，并维护连接状态与错误列表。
- `scene/page/diorama/model.mjs`：纯视图模型，不依赖 DOM 与 three。它把每张票映射到工位、归属颜色、附件与告警。`archipelagoOf` 给出每座岛的位置、铭牌与空闲标记，以及跨项目的卡住的票。
- `scene/page/diorama/world.mjs`：程序化几何，包括岛、海、调度岛、箱子、船闸、灯塔与灯笼。所有岛共用几何与材质。新 Scene 只重建场景内容，渲染器与 WebGL 上下文不变。
- `scene/page/diorama/camera.mjs`：正交固定等距相机，负责各机位的取景与平移边界。
- `scene/page/diorama/hud.mjs`：状态栏、告警框、机位按钮、项目坞、搜索、卡住的票与行程条。
- `scene/page/diorama/overlay.mjs`：跟随场景的票号、工位标签、铭牌与边缘箭头。标签尺寸在首次显示或文字变化时测量一次并缓存，舞台尺寸变化时清空缓存；画布尺寸由 `ResizeObserver` 提供，每帧不读布局。
- `scene/page/diorama/index.mjs`：`mountDiorama(stage, { scene, path, ticket, now, onView })` 连接以上模块，返回 `update(scene)`、`link({ online, failures })`、`dispose()` 与 `state()`。
- `scene/page/diorama/diorama.css`：沙盘与 HUD 的样式。

three.js 0.180.0 位于 `scene/page/vendor/`（`three.module.min.js`、`three.core.min.js`、`LICENSE.three`）。它不走 CDN，也没有构建步骤。模块用裸说明符 `three` 导入。

token 经 import map 带到每个模块：

1. `index.html` 的样式表与入口 `live.mjs` 直接带 `?t=__TOKEN__`。
2. import map 把 `three` 映射到带 token 的 `three.module.min.js`。
3. `three.module.min.js` 内部的相对导入先解析成无 token 的 `./vendor/three.core.min.js`，import map 再把它换成带 token 的 URL。
4. 沙盘模块之间的相对导入同理：import map 为每个 `./diorama/*.mjs` 写带 token 的 URL。
5. 新增页面文件时，同时登记到 `scene/server.ts` 的白名单与 import map。

### 读图规则

- 每个项目是一座同构的岛，有自己的水道、栈桥、船闸与灯塔。岛按 Scene 的项目顺序排成两列，位置只取决于顺序。
- 每座岛有一块铭牌：项目名、在途票数、闸关（部署屏障关闭时）与卡住的票数。有卡住的票时铭牌用告警色。
- 没有在途票的岛是空闲岛。只在 `pickup` 工位的票不算在途。有多个项目时，空闲岛只褪建筑，颜色淡向晴天天空色；地面、路径、栈桥与岛上水道保持原色。只有一个项目时不褪色。
- 多项目视图中，项目岛与调度岛的底座沉入海面，侧壁比地面深。浅色水线沿岛的轮廓围一圈，外侧的半透明接触阴影向光源反方向偏移，让岛与海面接触的位置可见。阴影不用渲染器阴影贴图。
- 海面有极淡的等距条带，始终静止，也遵循减少动态偏好。条带与水线的颜色由当前海色派生，随晴天、雾天、阴天和暗色天空一起更新；四种天空下都保留阴影与水线。只有一个项目时不画海面条带、接触阴影和水线。
- 调度岛只有一座钟楼。它的铭牌写 driver 的 `state` 与下次巡检时间（`nextScanAt`）。
- 位置表示阶段。工位来自 Scene 的 `station`：

  | station | 位置 |
  | --- | --- |
  | `pickup` | 账簿塔前 |
  | `work` | 工作间门前 |
  | `return` | 高台上的回流坡道 |
  | `gate` | 检验间 |
  | `review` | 审查拱门 |
  | `pack` | 封箱台 |
  | `merge` | 栈桥，按 `queuePosition` 从闸口向后排，没有位次的排在最后 |
  | `dispatch` | 闸前水道 |
  | `smoke` | 闸后水道 |
  | `repair` | 高台上的处置塔前 |
  | `human` | 高台上的人工台 |
  | 其他值 | 账簿塔旁，带「未知」标记 |

- 工作间数量取 3 和 `work` 工位票数中的较大值，不按 `workers` 画。不超过 5 间时排成一排；超过 5 间时，工作间排到高台左侧，每排 5 间，向岛的后方延伸。工作间标签写「工作间 · <work 工位票数>/<workers>」，容量只用文字表达。施工中的票点亮对应工作间的门。
- 箱子颜色表示归属：无、执行器、合并通道、处置Agent、人。未知归属使用「无」的颜色。
- 腰封与印章表示已封箱（`pack` 及之后）。木筏表示在水上（`dispatch`、`smoke`，或阶段为「已合并」仍在栈桥）。
- 胶带表示打回次数，来自 status 的 `corrections`。胶带是竖贴在箱子正面的浅色窄条，不翻过箱顶，不盖住审查章，与横向的腰封不同。条数等于 `count`，最多画 `limit` 条。`count` 达到 `limit` 时胶带改为深色，不发光，在红色的「人」箱上也能看清。没有 `corrections` 的票（还没有合并交接）不画胶带；`count` 为 0 时也没有胶带。
- 船闸与灯塔来自 `deployment`。有未通过的部署时闸门关闭；其中有 `paused` 或 `failed` 时灯塔为红色，否则为琥珀色。没有待处理的部署时闸门打开；项目配置了部署时灯塔为绿色，未配置时灯塔熄灭。闸门打开、项目配置了部署、但有 `unknownDeploy` 的票（已合并但 driver 没有提供 `deployment`）时，灯塔为冷灰色，外加一圈琥珀色细环，表示有部署但状态未知；熄灭的灯塔是暗色，没有细环。
- 有等人批的票时，人工台的灯笼变红。等人批按等待时间排，最久的在人工台。
- 告警标记：`tone` 为 `failed` 时为红色；`tone` 为 `attention`、工位未知，或项目配置了部署且票为 `unknownDeploy` 时为琥珀色。这种票工位名后加「部署未知」。项目没有配置部署时，已合并且没有 `deployment` 的票是正常状态，不告警，也不进「卡住的票」。
- 快照过期：driver 状态为 `unknown` 时不判过期；其他非 `ok` 状态直接判过期。`ok` 快照带 `nextScanAt` 时，只有 `generatedAt + 快照年龄` 超过下次巡检时间加 150 秒宽限才过期；没有 `nextScanAt` 时，沿用快照年龄超过 40 秒的规则。宽限取 150 秒：serve 每 30 秒醒一次，下一轮巡检比 `nextScanAt` 晚 0–30 秒开始；巡检读完账本才写新快照，这一段中位约 57 秒。一周日志里超过这个宽限的巡检约占 0.4%。driver 活着但巡检持续失败时，`nextScanAt` 仍会后移，页面要等 driver 在 5 分钟后把状态改为 `stale` 才显示过期。
- 天空：driver 状态 `unknown` 为暗色；维护不是 `running` 为阴天；快照过期为雾色；其余为晴天。有多个项目时，海的颜色随天空变化。
- 沙盘不画 Scene 没有的数据，也不画占位。基础设施与执行器预算不画。依赖暂停的供给柱也不画：全局暂停机制已由 OF-214 删除，driver 没有这项数据。

### 镜头与操作

- 相机是正交固定等距，没有旋转。机位 `1` 显示全部岛，机位 `2` 显示一座岛，机位 `3` 显示所选的票。数字键 `1`、`2`、`3` 直接切换机位。
- 只有一个项目时没有机位 `1`，也没有海与调度岛。
- 拖动平移，滚轮或双指缩放，点击箱子选票，双击箱子进入机位 `3`。平移与缩放都有边界；机位 `1` 的平移不超出群岛范围。
- 在机位 `1` 点击岛或铭牌进入该岛。`[` 与 `]` 切到上一座与下一座岛。
- 方向键平移，`Home` 回到当前机位，`Esc` 退一级：机位 `3` 回到机位 `2`，机位 `2` 先取消选择，再回到机位 `1`。
- 「卡住的票」跨项目列出告警的票，停留最久的在前，每条带项目名。点一条进入该票所在的岛并选中该票。「全部票」列出所有岛上的票。
- 票据带有效的 `https:` URL 时，「卡住的票」条目与所选票的行程条显示「打开记录」，可用 Tab 与回车在新标签页打开飞书记录；缺少 URL 或使用其他协议时不显示链接。
- 项目坞列出全部项目与卡住的票数，在机位 `2` 与 `3` 显示，在机位 `1` 隐藏。
- 在机位 `1`，有卡住的票的岛在画面外时，画面边缘出现指向它的箭头。点箭头进入该岛。
- `/` 打开搜索，按票号或项目名过滤，回车跳到第一条结果。焦点在搜索框或列表里时，数字键、`[`、`]`、`/` 与方向键不作用于沙盘。搜索框里的 `Esc` 只关闭搜索。
- 项目坞、卡住的票、全部票、搜索与行程条的按钮都可用 Tab 与回车访问。新 Scene 重建铭牌与箭头后，焦点回到同一座岛的同类按钮（铭牌或箭头）。
- 行程条显示所选票的票号、标题、归属、工位、阶段、停留时长与原因，并标出主线 8 段中的位置。主线下方一行小字：有 `corrections` 时写「打回 n/上限」并画上限个小格，已用的格子填色，达到上限时这一项变红；有 `lane` 时写「lane N」。缺哪项就不写哪项。合并队列中的票同时显示位次。`unknownDeploy` 的票在脚注另起一行：项目配置了部署时写「部署：未知 · driver 未提供 deployment」，没有配置时写「部署：不适用 · 未配置部署」。
- 行程条下方有「复制票号」与「复制详情」。详情每项一行：票号与标题、项目名与路径、工位、真实阶段、已观察时长，有 `corrections` 时加「打回：n/上限」，有 `lane` 时加「lane：N」，有原因时再加原因，`unknownDeploy` 的票再加行程条脚注里的部署那一行。安全上下文里用 Clipboard API；经 Nebula 地址打开的 HTTP 页面不是安全上下文，改用 `execCommand('copy')`。两种都失败时，提示手动选择行程栏中的文字。
- URL 跟随视图：机位 `2` 与 `3` 写 `?project=<路径>`，有选中的票时再写 `?ticket=<票号>`；机位 `1` 去掉这两项。`t` 保持不变。打开带这两项的 URL 回到同一视图；同号票按 `project` 选所在项目，没有 `project` 时取第一张。URL 指向的项目或票已不在 Scene 时，按默认机位打开。
- 系统开启减少动态时，相机直接到达目标，标记不浮动，箱子直接到达新工位。

### 连接与更新

- 新 Scene 原地更新：不重建 WebGL 上下文，相机、当前岛、机位与所选票保持不变。所选票离开 Scene 时取消选择，机位 `3` 退回机位 `2`；当前岛离开 Scene 时回到默认机位。
- 票换了工位时，箱子在 1.2 秒内移到新工位。相同 Scene 不会重播移动；箱子消失不代表成功。
- Scene 没有项目时卸载沙盘，写「暂无项目」；之后收到有项目的 Scene 时重新挂载。`update` 收到没有项目的 Scene 时在改动任何状态前抛出错误。
- 状态栏依次写连接状态（「已连接」或「连接断开」）、项目、天空说明（维护中、没有快照）、快照过期、`driver <state>`、快照年龄、维护模式与下次巡检时间。快照过期单独判断，维护中且过期时两项都写。断线时状态点变红。
- 状态栏下方的告警框在有内容时出现：断线后浏览器仍在重连（`EventSource` 为 `CONNECTING`）时第一行写「连接断开：画面停在最后一份快照，正在自动重连。」；事件流已关闭不再重连（`CLOSED`，例如 token 失效）时写「连接已关闭：请从 /ziikoo-driver 面板重新打开。」；`status`、`config` 命令失败或快照读取失败时每项一行，写命令、退出码与原因。收到恢复消息时删除对应行，重连成功时清空，服务再按当前状态重发。
- 首次连接和 SSE 重连按最新快照定位，不补播离线历史。页面隐藏（pagehide）时主动关闭事件流；浏览器前进后退缓存（BFCache）恢复（persisted pageshow）时重建连接并重新读取快照。
- 浏览器不能创建 WebGL2 上下文时，页面不留空白画布，写出原因并提示开启硬件加速或 WebGL。
- 生产页面在 `window.diorama` 上只暴露只读的 `state()`，供浏览器测试读取机位、选择与相机状态。

## 复制

头部的「复制」按钮（热键 `c`）把当前视图写成纯文本，放进按键所在界面的剪贴板，不带列宽填充和框线，被面板截断的内容也写全。详情复制完整时间线和全部最近异常，不受面板 15 行、5 条的显示限制。有筛选时只含匹配项，并写明筛选词。密钥类变量只写「已设置」或「未设置」，driver 的输出里本来就没有它们的值。

复制后弹一条提醒：成功写「已复制流水线（20 行）」，失败写原因，当前视图的主要数据还在读取时写「还在读取，稍后再复制」，不改动剪贴板。流水线页不等 doctor：票已读到时照常复制，项目徽标写成「检查中…」，和面板一致。终端经 OSC 52 写剪贴板时收不到回执，提醒写成功不代表一定粘贴得出来。

## 最近异常

详情的「最近异常」列出失败的命令和步骤、打回、转二线。转二线只包含三种情况：打回耗尽、步骤的基础设施预算耗尽、SCOPE 缺文件。`branchNo`、读取预算耗尽、恢复路径、合并通道、部署暂停和调度器发起的转二线不在这里，要看账本。打回和转二线的补充优先显示 worker 报告的 subject，其次是 evidence（审查打回时形如 `functions/api/v1/_admin-routes.js:155`）。没有这两项时不显示补充。

## 数据来源

面板只运行 `orca-factory-driver` 的四个只读命令，不读任何配置文件：`config --json`（每页都用，打开面板和按 `r` 时读取；配置组的页只读它）、`status --json`（流水线页的在途票、右上角的快照新鲜度、状态栏和提醒；打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时读取，停在运行组时每 10 秒重读一次，关掉面板后这个轮询停止；此外会话开始时读一次，之后在后台每 30 秒读一次，面板开着且停在运行组时后台这次跳过；热重载后面板仍开着时，后台把 10 秒轮询重新挂上，停在运行组时会话开始时那次读取也交给 10 秒轮询）、`doctor --json`（流水线页的项目徽标和健康页的检查列表；只在打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时运行，不随 10 秒定时重读，退出码 1 也照常解析；doctor 本机约需 30 秒，面板最多等 5 分 30 秒，比 doctor 自己的 5 分钟总时限多留 30 秒，让 doctor 超时后仍能写出报告）。详情的时间线来自执行器日志：`bash -c 'set -o pipefail; orca-factory-driver logs "$1" --json | { grep -E … || [ $? -eq 1 ]; }' _ <票号>`，只在打开详情和在详情里按 `r` 时运行。票号只作为位置参数传入，不拼进脚本；不符合 `ABC-123` 形状的票号不运行命令，时间线写「票号格式不对」。用 grep 只留下 `transition`、`ticket completed`、`command started`、`command exited`、`correction`、`resolver handoff` 六类行，再加上退出码非 0 或超时的 `external command` 行和 `result` 不是 `ok` 的 `external.end` 行，是因为长票的日志大部分是轮询记录，而面板读取命令输出最多只保留前 4 MiB，不过滤会截掉最新的部分；grep 没有匹配是正常结果，显示「没有执行器日志」；driver 失败时显示失败视图。日志里每个事件写成两行相同的内容，面板按整行去重。日志里没有 PR 编号，所以详情不显示 PR 链接。config 输出必须符合 `driver-config-v1` 契约（见 `driver/CONTRACTS.md`）。命令失败时面板画一个红框，写出退出码、stderr 前几行和「r 重试」；schema 或字段形状不对，或者出现面板不认识的调度键时，红框里写「输出无法解析」和原因。右上「↻ 刷新」重新取数。
