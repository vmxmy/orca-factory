# ziikoo-driver

Claude Code mod。斜杠命令 `/ziikoo-driver` 打开「Driver」面板，五页分两组。会话里第一次打开时在流水线页，之后再打开回到上次所在的页。

运行组看 driver 现在在做什么：

- 流水线：顶部是在途、部署屏障、待领计数，下一行是趋势小图：近 30 分钟每分钟一格，格高是该分钟内读到的最大在途数，没读到的分钟留空，面板窄时只画最近能放下的几格。每个项目一个圆角框，框线上是项目名和前缀，框内第一行靠右是检出与 core 同步徽标。每张票一行：票号、阶段轨道（领、施工、门禁、审查、合并、部署）、阶段名、在当前阶段停留的时长；下一行灰显标题，卡住时再多一行原因。轨道每段 2 到 6 列，随面板宽度伸缩；每段 5 列以上时轨道上方写全称，更窄时写单字（领 施 门 审 合 部）；连 2 列都放不下时只显示阶段名。没配部署的仓库不画部署点。颜色只表示状态：完成绿、当前蓝、需要注意黄（correction、处置 Agent、快照过期）、失败红。
- 健康：分「运行状态」（构建短 sha、服务状态、维护模式、状态快照）、「doctor 检查」（每项一行：中文名、通过 / 注意 / 失败 / 未知、原因）、「问题」三个框。

配置组看本机 driver 的生效配置：

- 模型：按仓库切换，「角色」框列出各角色的 Agent、模型、强度和来源键，底部是打回升档与小票审查阈值摘要。driver 施工首轮总用 default 档，strong 只在打回后升档时使用。
- 调度：`driver.toml` 的 8 个调度键，分为并发与限速、GitHub、Orca 与执行器、账本四个框。每行依次是中文名、带单位的值、来源和灰色的原键名；来源是 driver.toml 时高亮，是默认值时灰显。
- 环境：工厂目录、`driver.env`、服务环境与代理、工具路径各一个框；`driver.env` 的键只显示「已设置 / 未设置」，不显示值。

需要处理的状态画成标签：黄底或红底的反色文字，例如健康页的「注意」「失败」「未知」和项目徽标的「在 <分支>」「落后 N」「未提交改动」「core 待同步 #N」「core 未知」「检出未知」。正常状态（`main ✓`、`core ✓`、「通过」）是灰字。

头部两行。第一行是页签，每组前面是组名，当前组的组名加粗。第二行左边是服务状态点（`active` 时绿，否则红）、`orca-factory-driver` 和构建短 sha；右边在运行组显示快照新鲜度，在配置组显示 config 的取数时间，有读取进行中时再画一个转圈的加载动画，最右是刷新按钮。

## 打开

- 本仓库：交互会话自动加载 `.claude/skills/ziikoo-driver/`，直接输入 `/ziikoo-driver`。
- 其他仓库：`claude --plugin-dir <本目录的绝对路径>`，再输入 `/ziikoo-driver`。

面板打开后持有键盘：`r` 刷新，`1`–`5` 切页（运行组 1 流水线、2 健康；配置组 3 模型、4 调度、5 环境），Tab 或 ↑↓ 在按钮和仓库下拉之间移动，Esc 回到输入框。

## 数据来源

面板只运行 `orca-factory-driver` 的三个只读命令，不读任何配置文件：`config --json`（每页都用，打开面板和按 `r` 时读取；配置组的页只读它）、`status --json`（流水线页的在途票和右上角的快照新鲜度；打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时读取，停在运行组时每 10 秒重读一次，关掉面板后停止）、`doctor --json`（流水线页的项目徽标和健康页的检查列表；只在打开面板时停在运行组、切到运行组的页、在运行组按 `r` 时运行，不随 10 秒定时重读，退出码 1 也照常解析）。输出必须符合 `driver-config-v1` 契约（见 `driver/CONTRACTS.md`）。命令失败时面板画一个红框，写出退出码、stderr 前几行和「r 重试」；schema 或字段形状不对，或者出现面板不认识的调度键时，红框里写「输出无法解析」和原因。右上「↻ 刷新」重新取数。
