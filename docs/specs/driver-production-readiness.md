# 驱动器正式生产放行

基线：fd1d71d，2026-10-07。承接内置协调恢复修复，目标是可持续交付，而非仅进程存活。

## 当前缺口

- 合并通道反复报告 ZII-899 missing or conflicting durable handoff；必须核对真实 PR、head、gate/reviewer 与持久回执后恢复，不能伪造交接。
- 每轮发现重复扫描历史评论，配额恢复后再次耗尽。已有 Linear 投影 Spec / PR191，先核实实现与活跃归属，复用有效工作。
- systemd 代理未覆盖 Orca worker shell，Codex bootstrap 路由超时可复现；Linear 网络也存在间歇超时。
- 派发回执不能替代从领取到 Done/工作树清理的闭环证据。

## 实施与约束

1. 修复项目范围内的 worker 启动环境，保留既有代理覆盖值及内网直连，验证默认 Codex 启动。
2. 定位并修复交接阻塞；缓存/历史记录不授权合并，恢复仍需新鲜 gate、Codex reviewer、CI 与 exact head 证据。
3. 首次放行采用实时有界批量评论读取（最多五个 alias、每页100条、逐页完整校验），并补齐认领前的远端归属复核。不启用 PR191 的未完成投影。SQLite/Webhook/跨进程预算完整方案继续保留在 ZII-907～913，不能宣称本次完成。预算控制与动态回补不能关闭。
4. 通过 Codex 双轴审查及要求的 Make/项目 gate/CI 后合并部署，备份旧程序，保留持久状态、配置、在途执行器。
5. 投放一张无业务风险的文档测试票，验证调度器自主完成领取、worker、gate、Codex 审查、CI、合并、Done 与工作树清理。

不删除数据库/账本，不重置历史预算，不重开旧目标已取消的工作，不改并发政策或审查模型；不重启 Orca 来修复单个 worker。

## 放行证据

补充验证于 2026-10-08 发现两项当前主线缺口，纳入本次放行修复：执行器不得仅凭 `unverifiable` 与 `turn_start_unobserved` 超时停止 Agent，须保留未知状态且不重复派发；任务图的立即解锁排名仅计入完成该候选后全部未完成阻塞均解除的任务。两者均须先复现失败，再以行为测试验证修复；历史票的资源归属仍须单独核验。

- 每项行为修复先红后绿；使用现有公开生产边界验证，不仅测试私有 helper。
- 100票、五页issue、每票一页评论的公开 Runtime+真实HTTP边界夹具，每轮发现由105次降至25次（排除初始化/探测/关键复核）。仍实时读取历史评论、复杂度近似累加，不宣称缓存命中或零重复历史读取。生产独立记录调用量与时间窗，不能用夹具百分比冒充线上节省。
- 代理与 worker 启动在正常默认派工路径成功；瞬时网络失败有界退避、取消可结束，失败不被解释为空队列或任务完成。
- 无需手动改归属即可走通上述单票闭环。若门禁发现历史任务不再适用，必须逐票留下真实处理决定。
- 部署后至少观察 30 分钟且不少于 10 个调度周期；没有重复派工、永久交接错误或额度恢复后的紧密重试。保留失败恢复证据，合理配额暂停不计为服务崩溃。
- 在生产额度自然触发时记录低成本探测与恢复；不得人为消耗配额或改阈值制造成功。

## 工作顺序

合并诊断、Linear诊断、网络诊断并行；经归属核对后各自修复，统一集成；最后进行单票闭环与持续观察。所有子任务使用 Codex；自动生产任务与本协调任务不能同时编辑同一工作树。

- 总票：ZII-918；ZII-919 实时批量读取/认领复核；ZII-920 网络与启动配置；ZII-921 历史合并归属核验。最终验收依赖三者完成。
