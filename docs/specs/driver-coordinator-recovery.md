# 驱动器内置协调：恢复链路与上线验证

日期：2026-10-07。状态：实现前基线已核实。

## 问题与事实

目标是由 driver serve 独立完成定时扫描、认领、派发与恢复，不依赖 Orca 定时 Agent。现有 main 已有 scheduler.Serve 循环、单实例锁、Tick、Apply、Launch；AutomationDisabled 明确要求旧自动化关闭。因此不新增第二个协调循环，也不重新启用 agent-linear-scan。

发现的具体缺口：serve 的 statusBackend 包装器未转发 Runtime.ProbeLinearQuota。暂停后的调度器无法识别低成本探测能力，退回全量 Snapshot，可能再次耗尽动态恢复的额度。状态缓存还需防止测试污染，避免把测试票当生产运行证据。2026-10-07 14:53:20 服务正常退出，退出发起者尚未证实。

## 交付范围

1. 恢复真实 serve 包装链上的低成本配额探测；存在探测能力时，暂停轮次不得通过完整 Snapshot 探测。保留动态回补、失败退避、恢复阈值及旧后台契约。
2. 隔离测试状态输出，验证完整测试不会修改生产状态缓存；保留现有状态路径供已发布调用者使用。
3. 更新运维文档，明确唯一调度者、旧自动化互斥、暂停与 stale 的含义。完成 Codex 审查、CI、合并、备份旧二进制、部署与连续周期验证。

## 验收

- 通过 serveWithStatus 的行为测试复现暂停后的错误全量读取，先红后绿；低成本探测成功后恢复正常调度，失败时保持暂停且不派发。
- 重复启动继续受 singleton lock 限制；旧 Automation 开启时继续拒绝认领。
- 测试在隔离环境执行，对状态输出使用临时目录；生产缓存不出现夹具票。
- 上线保留配置、账本、SQLite、在途执行器和配额保护。不得重置数据或解除暂停伪造通过。
- 记录生产二进制提交、服务存活、旧 Automation 关闭、至少两个调度周期与探测日志。无可认领票不算调度故障；端到端票完成需独立证据。
